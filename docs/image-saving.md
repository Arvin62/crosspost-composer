# 导入并保存配图

## 日常使用

- **直接粘贴**：复制排好版的文章或 HTML 源码，粘贴到编辑区。工具保留正文、配图位置、宽度与图注，页面出现“下载并保存配图”提示，点击后开始处理。
- **导入文件**：打开“导入文章”，勾选“同时下载并保存配图”，再选择 HTML / Markdown 文件或粘贴源码并载入。未勾选时先显示占位，稍后也可以点击保存。
- 最多同时下载两张图片，解码与压缩仍依次进行，默认采用 **4K 高画质：最大宽度 3840 px、JPEG 质量 95%**，保留原始比例。也可以在设置中选择 1080P（1920 px、92%）、保留原图（不缩放、不重新压缩）或自定义。高画质 PNG 保持 PNG；小图不会被强行放大，当前图片不足长边 1920 / 短边 1080 px 时会提示。选中图片的“替代文字 / 图注”窗口可查看真实像素尺寸。
- 成功图片直接替换原位置的占位，随文章自动保存在当前浏览器，无需重新插图。GIF 保留动画；远程 SVG 暂不自动下载。像素尺寸与原始素材质量决定可保留的细节；4K 预设是宽度上限，不会将不同长宽比的素材裁切成 3840 × 2160。
- 失败图片保留原位置、替代文字和图注。“查看并替换”显示原因，可单张重试；也可以点击“打开原图”，在浏览器保存后选择本地图片原位替换；图片浮动工具条中的“替换”同样适用。
- 可以停止批量处理，已经完成的图片保留；切换文章、清空或重新导入时，会取消旧任务，避免异步结果覆盖新文章。
- 高清原图需要先完整下载，再在浏览器中按选定画质保存；大图可能需要几分钟。下载过程中显示收到的文件大小，可以随时停止；单张下载最多等待 10 分钟，服务器获取原图最多等待 2 分钟。
- 平台复制会阻止复制尚未保存的占位图。请完成保存、原位换图或删除后再复制。嵌入图片可移除原始外链依赖，公众号、汽车之家是否接受粘贴仍需在平台后台实测。

文章和图片保存于当前浏览器，并不自动同步到另一台设备。迁移时使用完整备份；备份包含待处理图片的位置与来源。成功嵌入的图片不再依赖原始链接。

## 自动下载的边界

浏览器能显示图片不等于允许读取文件：跨域限制通常由下载服务解决，但登录、验证码、地域限制或失效签名可能仍阻止自动下载。工具不会将验证页当作图片保存，也不会传送登录 Cookie。此时“查看并替换”提供“打开原图”和“原位换图”，保留正文位置、宽度和图注，避免重排整篇文章。4K 设置是处理上限，不会为本来不足 1080P 的图源制造真实细节。

## 下载服务

点击保存后优先通过浏览器直接下载；跨域、网络或图源错误时自动切换下载服务。浏览器等待图源响应头最多 8 秒，收到图片后仍允许高清大图完整传输。新图源无需逐个添加主机名单。某图源刚刚因跨域或网络问题直读失败但服务下载成功时，同一浏览器页面会在 5 分钟内优先通过服务读取该图源，减少重复等待；服务失败仍会补试浏览器。这只记录最多 100 个图源 origin 的临时偏好，不缓存图片字节或完整链接。服务只接收图片地址，返回图片文件；压缩在浏览器中完成。服务不接收正文，不保存文件，不记录请求 URL，也不转发浏览器的 Cookie、登录信息或文章来源页。服务器仅使用图源自身的公开 origin 作为 Referer 提示，兼容部分防盗链检查；图源拒绝该提示或返回非图片时，再尝试一次不带 Referer 的请求，两种策略共享总时限。

下载服务使用 Node.js 内置模块，无额外依赖。客户端和服务端单张上限均为 48 MiB；服务端限制超时、每种读取策略最多四次重定向（跳转循环额外允许一次带缓存刷新参数的尝试）、并发和请求频率。来源页面仍必须由部署者明确配置；图片主机支持 `public` 公网模式或 `allowlist` 精确名单模式，默认启动模式为名单模式，提供的部署示例显式选择公网模式。每次重定向都会重新检查主机与 DNS，拒绝本机、内网、链路本地和特殊地址；连接使用已经验证的 DNS 地址，避免二次解析。

### 本地启动

启动服务：

```bash
IMAGE_ALLOWED_ORIGINS=http://localhost:5173 \
IMAGE_HOST_POLICY=public \
npm run image-service
```

在另一个终端启动页面：

```bash
npm run dev -- --host localhost --port 5173 --strictPort
```

开发页面会通过 `/api/image` 转发给 `127.0.0.1:8787`。本地来源和端口必须与 `IMAGE_ALLOWED_ORIGINS` 相同。公网模式自动支持新图源，仍拦截内网和特殊地址。需要限制图源时设置 `IMAGE_HOST_POLICY=allowlist`，并在 `IMAGE_ALLOWED_HOSTS` 中配置精确主机名及重定向目的主机。

### 线上部署

GitHub Pages 仅托管页面，不能运行此 Node.js 服务。将 `server/image-service.mjs` 部署到自己的 Node.js 22.12+ 服务器，配置如下：

```bash
IMAGE_ALLOWED_ORIGINS=https://arvin62.github.io \
IMAGE_HOST_POLICY=public \
IMAGE_HOST=127.0.0.1 IMAGE_PORT=8787 \
node server/image-service.mjs
```

通过 HTTPS 反向代理公开 `/api/image`，转发到本机 8787 端口，保留原始 `Origin`，将代理读取超时设置为至少 150 秒。服务仅接受 JSON POST；健康检查为 `/health`。`IMAGE_HOST` 可改为容器需要的监听地址。公网模式只接受返回支持图片格式的公开地址，不代理任意网页。名单模式的主机配置不能填写 URL、通配符或私有网络主机。

将完整 HTTPS 接口地址填入页面“设置 → 图片下载服务”，例如 `https://images.example.com/api/image`。也可以在构建时配置：

```bash
VITE_IMAGE_SERVICE_URL=https://images.example.com/api/image npm run build
```

此地址是公开服务地址，不应包含密钥或访问凭证。页面的本机设置优先于构建默认值。服务的来源检查不是身份认证，公开部署还应由反向代理限制访问频率和总带宽；不要把服务作为不受限制的通用代理。服务默认不信任转发的客户端 IP，反向代理场景下内置频率限制按代理地址共享。

上线需要分别发布页面和服务，并在真实公众号、汽车之家后台验证粘贴。源码实现和本地测试通过不代表已经发布或目标平台上传成功。

### 配图状态与详情

配图状态位于编辑器底部，只显示待保存、失败或需要检查的数量，不占正文顶部。点击“配图”打开详情：失败图片可重试、打开原图并自行保存、原位换图；已保存但低于 1080P 参考尺寸的图片显示实际像素，可定位到正文或换成更高清的原图。清晰度建议不阻止编辑，也不会放大图片像素。保存说明仅在还有待保存图片时显示。
